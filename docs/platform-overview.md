# 现有平台概况

CampusClaw 面向中小学教师与学生，围绕本班资料、学习提问和教学智能体提供统一工作空间。小组将在现有平台上增量开发，对中小学教研智能体进行功能扩展。

## 已实现的能力

| 能力 | 当前平台功能 |
| --- | --- |
| 身份认证与班级隔离 | 服务端会话登录，区分教师与学生角色，按班级控制资料和教学资源的访问；口令以 bcrypt 哈希保存 |
| 班级资料管理 | 教师上传、编辑和管理本班资料，保存正文与元数据；文件读取经过服务端鉴权，数据和上传内容持久化 |
| 可追溯知识库检索 | 对资料正文切分、向量嵌入并建立索引，支持关键字、向量和混合检索；结果可回查资料与原文片段 |
| 提示词与 AI 技能 | 配置教学智能体的角色、提示词、技能与资料绑定，使回答围绕教学任务展开 |
| 流式学习会话 | 结合本班知识库生成回答，通过 SSE 流式展示；支持会话历史、消息时间与资料出处查看 |
| MCP 工具接入 | 登记与发现工具服务，将工具绑定到技能，执行带令牌的调用，并保留调用记录 |
| 工程与运行支撑 | 采用 OpenSpec 规约驱动开发，提供 Swagger 接口文档，并使用 Docker Compose 组织服务与持久化存储 |

功能概述对照[课程教学进度](https://devops.hello1023.com/index.html#schedule)，并结合已核对的平台接口、页面和配置整理。课程页面用于说明功能方向；具体接口与交互以平台实现和相应规约为准。

## 技术结构与兼容约定

平台采用 React 与 TypeScript 前端、Go 后端、MySQL、Qdrant、SSE 和 MCP。后续扩展保持现有功能与契约的兼容，改动对外行为前先修订相应规约。

| 当前实现约定 | 后续扩展方式 |
| --- | --- |
| API 使用 /api/，按接口文档的 HTTP 状态、资源响应与 error 字段判断结果 | 复用现有契约；统一业务码或版本前缀调整另立 change |
| 页面通过 App.tsx 的 page 状态切换 | 页面清单记录真实入口；引入 URL 路由时验证导航与兼容性 |
| 不透明 Bearer Token 对应服务端会话，客户端使用 localStorage | 按安全规则中的 E1 管理现有认证兼容；新认证设计先写规约与回归要求 |
| /health 提供进程存活检查 | 运行底座规划将就绪与存活分开，按对应 Scenario 验证 |
| 业务模块包含持久化与迁移逻辑 | 扩展按分层规则逐模块整合，审查数据访问边界 |
| 配置包含已文档化的非敏感参考值，检索阈值使用 VECTOR_SCORE_THRESHOLD | 复用实际键名，按配置字典检查必填项与数值范围 |
| 接口测试按 URL 路径组织 Python 用例 | 复用现有测试格式，并为新增场景补齐正常、失败与边界检查 |

E1 的范围仅为现有客户端认证行为，失效条件为认证改造 change 验收通过；扩展功能不得增加令牌持久化位置。

## 小组功能扩展

围绕小组项目选题说明，保留智能备课、智能命题、学情诊断、知识图谱、间隔复习、讲题模拟与学生互评七项候选。各模块复用现有登录、班级隔离、知识检索、会话、技能和工具能力，按独立 change 增量交付；首轮业务模块与优先级待小组确定。

第7课提交项目启动材料、工程规则与运行底座设计。后续运行任务按实际实现补全启动说明、门禁和验证记录，不以本页的功能概述代替小组仓库的运行验收。

## 工具准备

OpenSpec 1.13.0 可用 `npm install -g @fission-ai/openspec@1.13.0` 安装（需兼容 Node.js）；用 `openspec --version` 核对。仓库已执行 Codex 初始化，成员 clone 后复用已入库技能。升级工具作为维护动作评审。
