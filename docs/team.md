每次任务由实施者认领，另指定一名非作者评审人，一个工作日内响应；超时放到组内讨论，不由作者替代评审。涉及规约、规则和架构时三人共同确认。贡献以提交、PR、规约变更和真实验证记录为依据。

每条业务 change 不超过 tasks.md 的一组能力；单个实现提交只完成一个 task。超过 400 行手写应用改动时先拆任务或在 PR 写明不可拆原因，生成文件与锁文件单列。文档初始化作为第7课一次性 bootstrap 提交，后续应用改动遵守主干保护与 PR。

讨论首轮业务迭代时，对七项候选逐项核对用户价值、现有依赖、能否独立演示、失败路径及人力；形成决定后先建对应 OpenSpec change，不以本页候选表代替功能规约。
