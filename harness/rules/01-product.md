# 产品设计规则

适用于页面、交互与视觉变更；由根 AGENTS.md 触发读取。以下为后续实现的目标约束。

| 规则 | 检查方式与不通过条件 |
| --- | --- |
| 每个入口声明角色、用户任务、对应 Scenario；服务端决定权限 | 逐入口反查 Scenario；找不到用户任务或存在仅前端授权即退回 |
| 维护真实页面清单；当前平台为 App.tsx 的状态键，禁止编造独立路由 | 对照下表及源码；新增 URL 路由须有兼容规约与前进/后退验收 |
| 每个数据视图具备加载、正常、错误、空状态，检索另有无命中状态 | 人工注入慢响应、失败、空数据；无限加载、白屏或将失败显示为空均为缺陷 |
| 表单选择文件即校验类型/大小；其他文本提交时 trim/非空/长度检查，枚举不自行纠正 | 测空白、上限、上限加一、非法枚举；服务端仍须做相同边界检查 |
| 提交中禁重复触发，取消与失败后可恢复；去重副作用仍由后端保证 | 连点与重试观察写入数；产生重复记录或控件锁死即失败 |
| 复用组件与视觉令牌，间距 4/8/12/16/24/32，字号 14/16/20/28 | 抽查新增页面；无说明的自造基线先修正或书面例外 |
| 正文对比度至少 4.5:1，大字至少 3:1；控件有 label，焦点可见 | 键盘走完登录→资料→提问；无法操作或读屏无名称即失败 |
| 响应式在 375/768/1280px 核对，窄屏不横向溢出，主要触控目标至少 44px | 在三档尺寸核对同一场景 |
| 流程功能先列枚举、转移和各状态操作；终态修改须有入口和留痕 | 并发处理同记录，后到者收到冲突，不能静默覆盖；客户端不得直接设置目标状态 |
| 导入导出只在对应 change 明确后实现，上限/整批校验/错误行号和脱敏范围须在场景写具体 | 混入一条非法数据验证整批拒绝；越权导出包含任何他班数据即失败 |

## 状态文案与术语

加载：“正在加载…”；空列表：“这里还没有资料”，仅给当前角色有权执行的下一步；错误：“资料读取失败，请重试”，若持续失败提供联系教师的动作；检索无命中：“本班资料中未找到相关内容”，提供换关键词或联系教师补充资料。正常态展示真实数据，不能用示例冒充已保存内容。

统一用语：班级(class_id)、资料(material)、切片(chunk)、出处(citation)、智能体(agent)、技能(skill)、会话(conversation)、作业(assignment)。前端术语不自行改动既有字段或协议；新字段以规约为准。

违反时修复对应视图与清单；确需例外写入本文件并说明范围、理由和失效条件。
