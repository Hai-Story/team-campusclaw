# 测试规则

每次开工读取；编写测试时调用 $campusclaw-add-tests。用例先有来源，结论只对应实际运行范围。

| 规则 | 检查方式与不通过条件 |
| --- | --- |
| 单元测试覆盖业务规则；接口测试覆盖每个 Scenario；端到端覆盖教学主路径 | 测试名/注释写 Requirement 与 Scenario；无法追溯即先明确目的 |
| 每项能力按正常/失败/边界组织，至少覆盖参数非法、无权限、不存在、依赖故障 | 维护两列表映射；任一规约场景无用例不得归档 |
| *_test.go 随被测包，前端行为测试在 frontend/tests，接口 Python 用例沿用 apitest/cases/<URL>/<METHOD>.py | 迁移时验证工具实际识别文件，不能仅按文件名宣称执行过 |
| 单元测试用模型/向量/MCP/时钟替身；真实集成另列环境和开关 | 断网单元仍可执行；真实网关调用需当前任务授权，记录用量且不泄露内容 |
| A/B 班、教师/学生使用隔离测试库或 schema，前后清理，禁止借生产数据 | 反序/随机顺序结果一致；越权测试必须核对写入与数据集合 |
| 断言语义值与副作用；只断言不报错或形状不够 | 在隔离副本故意去掉关键授权/边界检查，对应用例应失败，随后恢复；不能修改真实环境 |
| 失败非零退出，阻断合并；跳过写理由与跟踪项，不能计为通过 | 报告列 PASS/FAIL/SKIP，核对命令退出码；不删断言让结果变绿 |

## 信号口径和缺陷判定

现有接口按 OpenAPI 的 HTTP 状态、返回字段和数据副作用判定结果。后续如某接口经规约引入独立业务码，则以文档业务码判断成败并检查数据，不因 HTTP 200 一项判“被放行”。中间件 405/413/415 与无体204按文档的HTTP信号处理，未知业务码记待确认而非编造。

- 被当成成功：负向请求得到约定成功信号、产生约定外写入或返回不该看的数据。
- 被放行：权限负向用例实际拿到越权数据或写入生效。
- 被误拒：合法请求缺成功信号或约定副作用。
- 未处理故障：未捕获异常、堆栈或无法说明原因/下一步的笼统错误；不把所有受控503等同崩溃。

功能检查包括缺必填、空白/长度边界、0/false筛选、稳定分页、日期偏移和批量混入非法行。安全检查包括账号枚举、横/纵越权、权限字段注入、附件归属与SQL/页面注入。

性能预算按接口规约：运行底座健康检查总预算3秒；普通非模型列表正向 p95≤500ms（100次、并发1、独立测试环境），超过300ms标记。对应change先固定合成数据规模、预热步骤、执行命令和计时边界；复测沿用同一条件，超500ms不通过。模型首字与总时长在相应change写明数值后再验收。

## 阶段命令

第7课：`openspec validate 2026-10-28-team-project-kickoff --strict`、`git diff --check`。后续代码阶段需先实施统一门禁 `make check`，包含格式、Go vet/build/test、前端类型与行为、规约/OpenAPI同步、密钥/依赖扫描；真实集成和异机启动单列，缺失门禁不能用文档检查替代。
