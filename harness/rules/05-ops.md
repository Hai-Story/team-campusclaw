# 部署运维规则

适用于后续运行、构建、配置、日志和发布。调用 $campusclaw-release 执行有明确授权的发布；本课只准备设计。

| 规则 | 检查方式与不通过条件 |
| --- | --- |
| 锁定依赖、保留锁文件、多阶段构建；镜像用提交号/版本号，跨环境同镜像只换配置 | 两次干净构建核对依赖及内容；无版本锁定或用latest发布即退回 |
| 开发/隔离测试/生产配置分开，机密运行时注入，仅web对外映射 | 检查Compose和镜像层；机密进构建参数或api/db/向量库意外公开即失败 |
| 匿名/health聚合就绪、/live存活；不返回内部地址 | 按运行底座S4-S7验证；健康请求不做真实模型生成或计费调用 |
| 优雅停机最长10秒，单行JSON请求日志包含时间/级别/模块/请求标识/方法/路径/状态/耗时 | 在途请求与停止信号测试，逐行解析日志；机密或正文进日志即失败 |
| 发布前测试环境演练回滚与兼容迁移；单实例维护或蓝绿方案须在change写明 | 不强制现阶段上多副本；选定方案记录停机窗口、前版标签与失败分支 |
| 迁移先增兼容结构，切换验证后再清旧；删除最后做 | 新旧版各启动验证；回滚不能依赖已删字段 |
| 数据每日备份，保留7天，目标RPO≤24h/RTO≤30min；每学期至少演练一次 | 真实恢复到隔离实例并记录耗时；没演练不宣称恢复目标已达成 |
| 定义请求量/错误率/耗时/依赖状态指标，告警5分钟错误率>5%或就绪连续失败3次 | 后续监控change实现；告警责任角色为部署负责人，排查就绪/日志后按已验方案回滚 |
| 模型与检索调用在各change规定主体限流、预算与超限错误，默认不无限重试 | 超额请求核对拒绝信号与重试建议；不把限流失败显示成空数据 |

发布顺序：固定提交与镜像→备份→兼容迁移→发布→就绪与主路径核对→标签与脱敏记录；失败按事先演练的前版回滚。本次无运行版本，不打v0.0.1-skeleton。

发布记录放 docs/releases/YYYY-MM-DD-version.md，包含提交、镜像摘要、命令、环境、结果、回滚耗时与责任人；性能阈值是目标，不是未经测试的达标承诺。
