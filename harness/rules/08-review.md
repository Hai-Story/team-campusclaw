# 评审与完成定义

每次工作读取，使用 $campusclaw-review-change 形成可核对结论。

变更完成同时满足：规约场景与越权场景验证通过、匹配阶段的门禁通过、文档同步、证据归档、非作者评审确认；涉及提示词加评测，涉及数据加迁移/恢复证据。第7课文档交付完成只表示启动材料已可审阅，不表示运行规约验收通过。

| 事项 | 检查方式 |
| --- | --- |
| 一个change一组能力、实现一次一个task，超400行手写应用改动拆分或说明不可拆原因 | 对照tasks与diff，生成文件单列，不靠文件数掩盖范围 |
| 适用规则能追溯到Requirement/Scenario、task verify和实际结果 | 评审结论引用规则路径与条目、场景编号、任务编号和证据位置；输入、步骤、预期值或失败信号缺失则先补规约，不能判通过 |
| 人审场景、授权、迁移与教学价值；Harness核对规范一致；格式工具处理排版 | PR或评审记录写各自结论，自动检查与人工评审结论分开记录 |
| 评审人非作者，一个工作日内响应，超期交小组讨论 | 按PR作者/评审与时间核对，不自批 |
| 主干保护与访问权限在平台核对，业务代码只经PR合并 | 验证规则生效和非作者review，不能以“有AGENTS.md”当作平台保护已启用 |
| 提交正文含Change/Verify/Evidence，命令和路径真实 | 抽三条提交反查来源；无运行记录则写待验证，不写PASS |
| 规则、规约、门禁、构建和发布文件变更写明原因，由人确认 | 不因工具执行成功而跳过语义审查；例外须书面、限范围、设失效条件 |
| 所有必需任务通过后归档，由归档更新openspec/specs，运行基线才打skeleton标签 | 任务仍未跑、组员复现未完成则不归档，不写全课验收通过 |

## 代码核查

AI 初稿须经过逐段自查 → 非作者交叉评审 → 测试与证据核对 → PR 合并；未完成不得合入 main 或上线。

| 核查对象 | 必须回答的问题 |
| --- | --- |
| 接口入口 | 参数类型与边界是否校验？是否验证资源归属？响应是否含多余敏感字段？ |
| 业务逻辑 | 是否逐条满足 Scenario？状态转移及失败出口是否完整？ |
| 数据库操作 | 多处写入是否同事务？唯一性是否由约束保证？并发失败是否回滚？ |
| 公共函数 | 是否重复复制逻辑？异常是否被吞掉？能否复用已有实现？ |
| 错误处理 | 非法输入、依赖故障、约束冲突是否有明确结果？是否泄露内部信息？ |
| 安全与隐私 | 是否防越权、输入注入和敏感信息泄漏？日志与展示是否脱敏？ |
| 性能 | 是否循环逐条查库？过滤条件是否有索引？列表是否分页？ |

评审记录逐项填写七个维度：需求覆盖率、需求一致性、失败路径、查询性能、重复代码、安全风险、并发/事务/一致性高风险。需求覆盖按场景标记已实现/部分实现/未实现；其他维度写具体文件位置、判据与结果，不适用时注明原因。

每个被审文件给出“可用 / 待修改 / 风险无效”：可用仍须通过测试与非作者评审；待修改列出问题并复审；风险无效用于越权、数据错乱或无关实现，退回重写。每条高风险结论写全“用什么手段查 / 查了什么 / 判据 / 结果”，并引用对应 Scenario。

异步与安全证据统一在 reports/：security-precheck.md、security-baseline.md、risk-authz.md、risk-concurrency.md、risk-transaction.md、review-01.md。交叉评审须由另一名成员独立复现至少2项，记录实际输出与判定；自动检查不能代替该确认。其他变更证据沿用docs/changes/<change>/；已有启动记录保留原路径。

证据至少记录日期、环境、固定提交、命令/步骤、退出码、观察结果与范围。报告与截图不含口令、令牌或学生真实内容。
